# 古诗内容数据规范 v0.1

## 1. 内容生命周期

每条诗词及题目必须处于以下状态之一：

`draft` -> `in_review` -> `published` -> `archived`

- 只有 `published` 内容可提供给学习端。
- Excel、爬取或外部来源先进入 `staged_poems`，审核通过后才可合并到 `poems`。
- 所有修改必须保留来源字段；错误或版权不清晰的媒体不可发布。

## 2. 诗词必填字段

| 字段 | 规则 |
|---|---|
| `slug` | 英文小写、连字符；稳定且不随标题修改，例如 `wang-lushan-pubu`。 |
| `title` | 标准题名；保留必要篇目标识，如 `饮酒·其五`。 |
| `author` / `dynasty` | 采用统一作者、朝代表，不写在正文中。 |
| `body` | 每句一行；保留中文标点；不混入翻译、注释。 |
| `pinyin_lines` | JSON 数组，长度必须等于正文行数；每项只对应一行原文。 |
| `brief_analysis` | 80-180 字，适合“读诗小笺”。 |
| `detailed_analysis` | 250-800 字，解释结构、关键字词、修辞和情感。 |
| `creation_background` | 80-300 字；无法确认时明确标为“背景待考”。 |
| `source_reference` | 版本、教材或可信参考来源。 |

## 3. 分类要求

每首发布诗至少具备：

1. 一个学习库：小学必备、课外推荐或进阶学习。
2. 一个年级或明确标为课外/进阶。
3. 一个题材、一个体裁、一个时代。
4. 至少一个“古诗与物”意象标签。

可选关联包括历史事件、诗歌流派、作者画像、关联诗词和音频。

## 4. 媒体与版权

- 每首发布诗需要一张 `detail_background`，并可选一张 `cover`。
- 媒体记录必须包含 URL、替代文本、署名与版权状态。
- 使用 AI 生成图时，`copyright_status` 标注为 `generated`；外部图片必须可追溯授权。
- 朗读音频需要记录朗读者、版本、时长与逐句时间轴。

## 5. 题目规范

- 每首可进行深度学习的诗至少有 3 道已发布选择题。
- 每题 3-4 个选项，且仅一个正确项。
- 必须提供解析，说明正确理由而不是仅给答案。
- 题目覆盖字词、画面/情感、表达手法或背景中的至少两类。

## 6. Excel 导入规则

当前 `古诗.xlsx` 为原始内容来源。导入工具只写入 `staged_poems`：

- 自动提取标题、朝代、作者和正文。
- 缺少标题、作者或正文时写入 `validation_errors`。
- 导入不直接覆盖 `poems`；编辑审核后才执行合并。
- 需要补齐拼音、解析、背景、分类、媒体和题目后，才允许发布。
